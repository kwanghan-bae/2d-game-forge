- 기준 브랜치: `main`
- 기준 상태: V4 수익화·저장 복구 hardening까지 `main`과 `origin/main` 반영됨
- 마지막 기록: 2026-09-08

## 현재 완료 범위

`main`에는 모노레포 골격과 `@forge/core` 계약, `dev-shell` 포털, 인플레이션 RPG
게임, 런 영속화와 메타 진행, 모바일 UX, 콘텐츠 확장, Forge-UI, 수익화 기반이
반영되어 있다. 원스토어 native wire와 각 스토어 출시 작업은 별도 후속 범위다.

V4 `신의 마을: 영원의 후원자`는 `inflation-rpg` 기본 진입점으로 제공되며,
V3는 `inflation-rpg-legacy`와 `StartLegacyGame()`으로 보존된다. V4 전용 저장 키,
오프라인 정산, 7개 시설·3개 지원 에이전트·3개 Realm, 원정 결과 확인,
native purchaseUpdated/복원/광고 lifecycle 경계가 구현되어 있다. 현재 game Vitest
400개 파일·3,633개 테스트, V4 E2E 32/32, game E2E 46/46, dev-shell portal E2E 5/5,
workspace typecheck/lint/circular/build가 통과했다. 실기기 원스토어 sandbox 결제·복원·환불 QA는
Android 장비와 sandbox 계정이 필요한 별도 단계로 남아 있다.

native onestore Web 테스트 7/7과 Android pending 구매 슬롯 단위 테스트 4/4,
`compileDebugKotlin`·`assembleDebug`도 통과했다. 구매 성공 callback은 요청 상품과
일치할 때 pending 슬롯을 정확히 한 번만 소비하고, 다른 상품의 정상 callback은
요청 상품 callback 또는 timeout까지 pending을 보존하며, 중복 callback은 이미 응답한
PluginCall을 다시 건드리지 않는다. 이는 패키지·디버그 APK 빌드 검증이며, 실제
원스토어 sandbox 계정과 실기기 결제·복원·환불 동작 검증을 대체하지 않는다.

`MonetizationService`도 하위 IAP manager가 아닌 서비스 자체의 복원 경계에서 구매
레코드를 재검증해, product id만 가진 malformed `ad_free` payload가 광고 제거 권한으로
승격되지 않도록 했다. 정상 ad-free·소모성 구매와 취소 구매 회귀도 서비스 테스트로
고정했다.

AdMob rewarded 응답도 `type`·양수 유한 `amount`를 갖춘 보상 레코드인지 확인한 뒤에만
성공으로 전달한다. 취소·0 보상·빈 타입·비유한 금액 응답은 게임 재화 보상으로 이어지지
않도록 native 광고 경계에서 차단했다.

원스토어 상품 조회의 `priceAmountMicros`도 알려진 유료 카탈로그에 맞춰 양수 safe-integer로
제한해, 0원·정밀도 손실 가격이 구매 캐시와 상품 UI에 남지 않게 했다.

IAP manager와 MonetizationService의 상품 ID도 런타임에서 카탈로그를 다시 확인해, 타입을
우회한 알 수 없는 상품 요청이 provider 호출이나 카탈로그 예외로 이어지지 않게 했다.

V4 monetization adapter는 외부 광고·결제 브리지에서 런타임 `true`만 보상·광고 제거
권한으로 인정한다. 타입 계약을 우회한 truthy 문자열·객체는 진행이나 결제를
오염시키지 않고 provider failure로 격리한다.

광고·결제·복원 provider와 native monetization bootstrap이 예외 없이 영구 pending
상태가 되는 경우도 60초 deadline 뒤 provider failure로 정리해 로컬 게임 진행이
멈추지 않도록 하고, 네 경로의 timeout 회귀를 고정했다.

원스토어 Android 초기화·상품 조회·복원·승인/소비 응답 또는 구매 callback이 유실되어도
native 대기 호출이 영구 점유되지 않도록 60초 뒤 실패 응답과 재시도 가능한 정리 경계를
추가했다. Kotlin compile과 debug APK assemble을 다시 통과했다.

시설 카드의 강화 비용을 `+` 버튼의 접근성 라벨에만 숨기지 않고 한국어 금화·재료
수치로 항상 노출해, 모바일에서도 다음 시설 목표와 병목을 즉시 비교할 수 있게 했다.

지원 에이전트 카드에도 특성(정밀 제작·안전한 축원·위험 경로 감지)을 표시해,
플레이어가 작업 배정 전에 담당자별 차이를 확인할 수 있게 했다.

TownHub의 손상된 개입 충전·영웅 HP도 표시값뿐 아니라 즉시 회복·원정 후퇴 버튼의
활성 조건에 반영해, `NaN`·무한대 저장 payload가 보상형 액션을 호출하지 않게 했다.

원정소도 길잡이 누락·비유한 피로도를 “길잡이 정보 확인 필요”로 구분해,
손상된 상태를 “길잡이 사용 중”으로 오인하지 않게 했다.

원정소도 준비 비용이 부족한 Realm의 길잡이·혼자 출발 경로를 미리 비활성화하고,
현재 보유량과 필요한 재화를 카드 안에서 안내해 클릭 후 오류에 의존하지 않게 했다.

영웅 상세 화면은 손상된 in-memory 장비 목록을 빈 장비 상태로 격리해, 복구·재개
중에도 화면 전체가 중단되지 않도록 했다.

저장 schema의 사가 title·text도 공백 문자열을 무효 payload로 거부해, 빈 기록이
정상 저장처럼 남거나 다음 ID namespace를 오염시키지 않도록 했다.

시설 task의 표시명과 원정 패배 원인도 non-empty 문자열로 제한해, 작업 완료·패배
결과 화면이 빈 문구를 정상 기록으로 복원하지 않도록 했다.

설정의 구매 복원은 provider 응답 대기 중 버튼을 비활성화하고 `구매 복원 중`을
표시해, 모바일 연속 탭이 중복 native 요청으로 이어지지 않게 했다.

광고 제거 구매도 훅의 in-flight 상태와 화면 버튼 잠금을 연결해, 스토어 응답이
끝나기 전 중복 구매 요청을 차단하고 `구매 처리 중` 상태를 노출한다.

보상형 광고의 오프라인 2배·시설 즉시 완료·개입 충전도 provider 응답 중 버튼과
연관된 작업 변경을 잠그고 `처리 중` 상태를 노출해, 보상 경합과 모바일 연속 탭을
화면 단계에서 명확히 차단한다.

영웅 전투력 계산도 in-memory 스냅샷의 누락 숫자 필드를 최대 전투력으로 오인하지
않고 0으로 격리해, 손상된 화면·원정 예측이 보스 승률을 과대 표시하지 않게 했다.

workspace typecheck가 실제로 생성하지 않는 `tsbuildinfo` output을 기다리며 경고하지
않도록 Turbo typecheck task의 output을 빈 배열로 정리했다.

명시적 V3 영웅 가져오기도 active task·원정·사가가 공유하는 V4 ID namespace를
확인해, 가져오기 직후 저장이 충돌로 무효화되지 않도록 saga ID를 회피 생성한다.

V3 영웅 가져오기 adapter는 문자열이더라도 비어 있거나 공백뿐인 legacy 장비 ID를
제외하고, 알 수 있지만 비어 있지 않은 기존 ID는 그대로 보존한다. 따라서 오래된
저장의 장비 배열이 V4 장비 레벨 map과 UI에 빈 key를 만들지 않는다.

V4 저장 schema도 영웅 장비 ID와 장비 레벨 map key를 non-empty 문자열로 검증해,
구버전 hydration 경로가 공백 장비를 다시 저장 가능한 상태로 복원하지 않게 한다.

V4 재화와 시설 작업의 재화 payload는 안전한 정수만 저장하도록 검증해, 소수 재화가
화면 표시와 실제 지불·환불 계산 사이에 숨은 잔액으로 남지 않게 한다.

회춘·시설 작업·시설 강화의 지불 경계도 금화 잔액이 유한한 안전 정수가 아닐 때
원본 저장을 그대로 보존하고, `NaN`·무한·소수 금화가 새 저장으로 전파되지 않게 한다.

원정 출발 전 영웅 HP와 HP 최대값도 저장 가능한 유한 범위인지 확인해, 손상된
메모리 스냅샷이 `null` HP 원정으로 진행되거나 준비 비용을 차감하지 않게 한다.

신의 개입 즉시 회복도 같은 HP 경계를 사용해, 손상된 HP 스냅샷이 충전을 소비하거나
`null`·무한대 HP를 새 저장에 쓰지 않게 한다.

지원 에이전트 휴식도 피로도가 유한한 0~100 범위를 벗어나면 원본 저장을 보존해,
손상된 피로도가 새 저장으로 전파되지 않게 한다.

시설 작업과 원정에 에이전트를 배정할 때도 동일한 피로도 범위를 확인해,
`NaN`·무한대 상태가 활성 작업 링크에 남지 않게 한다.

오프라인 보상 callback도 지급 대상 잔액이 안전한 정수가 아닐 때 clone·시각 갱신을
수행하지 않아, 보상 경계에서 소수·`NaN`·무한대 재화가 확산되지 않게 한다.

시설 취소와 원정 후퇴 환불도 대상 잔액을 먼저 확인해, 손상된 재화 상태에서
작업·원정만 종료되고 환불이 유실되는 경로를 차단한다.

시설 작업 완료도 due 보상을 적용하기 전에 대상 잔액을 확인해, 손상된 재화에
보상을 더한 뒤 작업만 삭제하는 경로를 차단한다.

원정 보상·패배 환불도 정산 전 대상 잔액을 확인해, 손상된 재화에 보상을 더한 뒤
원정만 종료되는 경로를 차단한다.

지원 에이전트의 신뢰도·레벨·피로도도 작업 배정·정산·후퇴·휴식 전에 함께 검증해,
손상된 에이전트 상태가 JSON clone을 거쳐 저장 가능한 값으로 위장되지 않게 한다.

오프라인 정산이 손상된 상태로 차단되면 `lastProcessedAt`과 `updatedAt`도 소비하지
않아, 저장 상태를 복구한 뒤 같은 보상 창을 안전하게 다시 시도할 수 있게 한다.

위험 원정 결과 확인도 중간 `traveling` 상태를 외부에 노출하지 않는 원자 전환으로
보강해, malformed 재화·에이전트 정산 실패 시 보류 원정과 저장 객체 identity를 그대로 보존한다.

원정 결과의 malformed·null 보상 payload도 화면을 중단시키지 않고 `획득 보상 · 없음`으로
표시해, 저장 복구를 우회한 런타임 오염에서도 결과 카드와 사가 안내를 유지한다.

시설 작업·원정의 완료 시각이 `NaN`·무한대·음수로 오염된 메모리 상태에서도 정산·환불·
광고 즉시 완료가 보상을 지급하지 않고 원본 작업을 보존하도록 경계를 강화한다.

GitHub Actions의 별도 E2E job도 원스토어 native workspace를 먼저 빌드하도록 보강하고,
GitHub runner에서 느려지는 연쇄 시뮬레이션 회귀에는 명시적 timeout을 적용해 로컬과
동일한 검증 경로를 유지한다.

## 완료·검증된 V4 안정화 범위

### V4 수익화·재개·결과 화면 안정화

- native purchaseUpdated 이벤트를 검증 후 ad-free entitlement에만 반영한다.
- V4 root 교체·StrictMode·unmount에서 native handle, IAP listener, AdMob banner와
  rewarded ad의 폐기 경계를 유지한다.
- ONE store service 단절 뒤 사용자 구매·복원 액션에서 provider connection을
  재확인하고 listener 등록을 재시도한다.
- 활성 작업 중이거나 최대·비정상 레벨인 시설 강화 버튼을 UI에서 비활성화한다.
- 손상된 오프라인 결과 collection도 빈 안전 상태로 렌더링하고, 재화·장비·작업
  결과를 양수 보상 기준으로 표시한다.
- 작업·활성 원정·최근 결과·사가가 동일한 ID를 공유하는 부분 저장을 복구 단계에서
  격리해, 서로 다른 완료 경로가 같은 기록을 덮어쓰지 않게 한다.
- native monetization getter가 예외를 던져도 entitlement·광고 사용량을 안전한 기본값으로
  표시하고 복원 액션이 게임 렌더링을 중단하지 않게 한다.
- 사가 화면의 in-memory 항목이 객체·배열로 오염되어도 안전한 문구와 고유 key로 기록
  화면을 계속 표시한다.
- 저장 envelope의 task·원정·결과·사가 식별자는 빈 문자열을 허용하지 않아 손상된
  완료 경로가 빈 ID namespace에 진입하지 못하게 한다.
- `output/`, `tmp/` 미추적 사용자 산출물은 작업 범위에서 제외한다.

### C1167 — 시공 역설 나선 밸런스

- `paradoxSpiral.ts`의 100층 전투 곡선과 방어 계산을 조정한다.

  효과를 검증한다.
- 변경을 마치면 시스템 테스트, 타입 검사, lint와 전체 회귀 검사를 실행한다.

3. **C1167 밸런스 검증** — 100층 곡선, 변칙 디버프, 보상 경제를 확정한다.
4. **C1168 서사 확장** — 역설 수호자 크로노스와 층계별 마일스톤 전승을 추가한다.
5. **C1169 영구 진행 연동** — 최고 도달층 보너스와 기존 saga 진행을 연결한다.
6. **C1170 종합 비평** — 시스템·밸런스·서사·화면을 함께 검토하고 다음 로드맵을
   갱신한다.
7. **출시 후속** — 원스토어 native wire(Phase 5a-1), Google Play(Phase 5b),
   App Store(Phase 5c)의 순서와 필요성을 검토한다.

## 완료 기준

새 기능은 설계 문서, 구현, 테스트, 검증 결과가 서로 연결되어야 한다. 저장 데이터,
새로 고침, 런 종료, 다음 런 시작과 주요 화면에서 상태가 일관되게 유지되는지
확인한다. 밸런스 변경은 산술 또는 simulation 근거를 남기고, 화면 변경은 모바일
터치 영역과 핵심 E2E 흐름을 함께 확인한다.

  `병합:`으로 시작한다.

  유지한다.
