# 작업 현황과 다음 개발 방향

- 기준 브랜치: `main`
- 기준 상태: V4 수익화·저장 복구 hardening까지 `main`과 `origin/main` 반영됨
- 마지막 기록: 2026-09-08

## 현재 완료 범위

`main`에는 모노레포 골격과 `@forge/core` 계약, `dev-shell` 포털, 인플레이션 RPG
게임, 런 영속화와 메타 진행, 모바일 UX, 콘텐츠 확장, Forge-UI, 수익화 기반이
반영되어 있다. 원스토어 native wire와 각 스토어 출시 작업은 별도 후속 범위다.

V4 `신의 마을: 영원의 후원자`는 `inflation-rpg` 기본 진입점으로 제공되며,
V3는 `inflation-rpg-legacy`와 `StartLegacyGame()`으로 보존된다. V4 전용 저장 키,
오프라인 정산, 7개 시설·3개 지원 에이전트·3개 Realm, 원정 결과 확인,
native purchaseUpdated/복원/광고 lifecycle 경계가 구현되어 있다. 현재 game Vitest
400개 파일·3,535개 테스트, V4 E2E 32/32, game E2E 46/46, workspace
typecheck/lint/circular/build가 통과했다. 실기기 원스토어 sandbox 결제·복원·환불 QA는
Android 장비와 sandbox 계정이 필요한 별도 단계로 남아 있다.

native onestore Web 테스트 7/7, Android `compileDebugKotlin`·`assembleDebug`도
통과했다. 이는 패키지·디버그 APK 빌드 검증이며, 실제 원스토어 sandbox 계정과
실기기 결제·복원·환불 동작 검증을 대체하지 않는다.

V4 monetization adapter는 외부 광고·결제 브리지에서 런타임 `true`만 보상·광고 제거
권한으로 인정한다. 타입 계약을 우회한 truthy 문자열·객체는 진행이나 결제를
오염시키지 않고 provider failure로 격리한다.

광고·결제·복원 provider와 native monetization bootstrap이 예외 없이 영구 pending
상태가 되는 경우도 60초 deadline 뒤 provider failure로 정리해 로컬 게임 진행이
멈추지 않도록 하고, 네 경로의 timeout 회귀를 고정했다.

원스토어 Android 초기화·상품 조회·복원·승인/소비 응답 또는 구매 callback이 유실되어도
native 대기 호출이 영구 점유되지 않도록 60초 뒤 실패 응답과 재시도 가능한 정리 경계를
추가했다. Kotlin compile과 debug APK assemble을 다시 통과했다.

시설 카드의 강화 비용을 `+` 버튼의 접근성 라벨에만 숨기지 않고 한국어 금화·재료
수치로 항상 노출해, 모바일에서도 다음 시설 목표와 병목을 즉시 비교할 수 있게 했다.

workspace typecheck가 실제로 생성하지 않는 `tsbuildinfo` output을 기다리며 경고하지
않도록 Turbo typecheck task의 output을 빈 배열로 정리했다.

명시적 V3 영웅 가져오기도 active task·원정·사가가 공유하는 V4 ID namespace를
확인해, 가져오기 직후 저장이 충돌로 무효화되지 않도록 saga ID를 회피 생성한다.

자율 진화는 다음 범위까지 진행되었다.

- 자율 진화 v1: 8개 페르소나와 100 cycle 완료
- 자율 진화 v2: cycle 101~200 완료
- C1159~C1164: 신격 보구와 무기고 기능, 전투 연동, 비평·로드맵 정리 완료
- C1165: 시공 역설 나선 절차적 엔진과 4종 변칙 생성기 구현
- C1166: 시공 역설 나선 탑 모달과 층계 등반 화면 구현

## 현재 진행 작업

### V4 수익화·재개·결과 화면 안정화

- native purchaseUpdated 이벤트를 검증 후 ad-free entitlement에만 반영한다.
- V4 root 교체·StrictMode·unmount에서 native handle, IAP listener, AdMob banner와
  rewarded ad의 폐기 경계를 유지한다.
- ONE store service 단절 뒤 사용자 구매·복원 액션에서 provider connection을
  재확인하고 listener 등록을 재시도한다.
- 활성 작업 중이거나 최대·비정상 레벨인 시설 강화 버튼을 UI에서 비활성화한다.
- 손상된 오프라인 결과 collection도 빈 안전 상태로 렌더링하고, 재화·장비·작업
  결과를 양수 보상 기준으로 표시한다.
- 작업·활성 원정·최근 결과·사가가 동일한 ID를 공유하는 부분 저장을 복구 단계에서
  격리해, 서로 다른 완료 경로가 같은 기록을 덮어쓰지 않게 한다.
- native monetization getter가 예외를 던져도 entitlement·광고 사용량을 안전한 기본값으로
  표시하고 복원 액션이 게임 렌더링을 중단하지 않게 한다.
- 사가 화면의 in-memory 항목이 객체·배열로 오염되어도 안전한 문구와 고유 key로 기록
  화면을 계속 표시한다.
- 저장 envelope의 task·원정·결과·사가 식별자는 빈 문자열을 허용하지 않아 손상된
  완료 경로가 빈 ID namespace에 진입하지 못하게 한다.
- `output/`, `tmp/` 미추적 사용자 산출물은 작업 범위에서 제외한다.

### 병렬 보호 작업 — C1167

현재 작업 중인 `paradoxSpiral.ts`와 관련 테스트는 이 V4 작업에서 수정하지 않는다.
밸런스·서사·영구 진행 작업은 기존 작업 흐름과 테스트를 보존한 채 별도 진행한다.

### C1167 — 시공 역설 나선 밸런스

- `paradoxSpiral.ts`의 100층 전투 곡선과 방어 계산을 조정한다.
- `paradoxSpiralBalance.test.ts`로 층계별 스탯 증가, 전투 깊이, 경제 보상과 변칙
  효과를 검증한다.
- 변경을 마치면 시스템 테스트, 타입 검사, lint와 전체 회귀 검사를 실행한다.

## 완료 기준

새 기능은 설계 문서, 구현, 테스트, 검증 결과가 서로 연결되어야 한다. 저장 데이터,
새로 고침, 런 종료, 다음 런 시작과 주요 화면에서 상태가 일관되게 유지되는지
확인한다. 밸런스 변경은 산술 또는 simulation 근거를 남기고, 화면 변경은 모바일
터치 영역과 핵심 E2E 흐름을 함께 확인한다.
