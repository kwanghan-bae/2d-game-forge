# 작업 현황과 다음 개발 방향

- 기준 브랜치: `main`
- 기준 상태: V4 오프라인 결과·시설 강화 UX hardening (`da7fc832`)까지 `main`과 `origin/main` 반영됨
- 마지막 기록: 2026-09-08

## 현재 완료 범위

`main`에는 모노레포 골격과 `@forge/core` 계약, `dev-shell` 포털, 인플레이션 RPG
게임, 런 영속화와 메타 진행, 모바일 UX, 콘텐츠 확장, Forge-UI, 수익화 기반이
반영되어 있다. 원스토어 native wire와 각 스토어 출시 작업은 별도 후속 범위다.

V4 `신의 마을: 영원의 후원자`는 `inflation-rpg` 기본 진입점으로 제공되며,
V3는 `inflation-rpg-legacy`와 `StartLegacyGame()`으로 보존된다. V4 전용 저장 키,
오프라인 정산, 7개 시설·3개 지원 에이전트·3개 Realm, 원정 결과 확인,
native purchaseUpdated/복원/광고 lifecycle 경계가 구현되어 있다. 현재 game Vitest
400개 파일·3,518개 테스트, V4 E2E 32/32, game E2E 46/46, workspace
typecheck/lint/circular/build가 통과했다. 실기기 원스토어 sandbox 결제·복원·환불 QA는
Android 장비와 sandbox 계정이 필요한 별도 단계로 남아 있다.

자율 진화는 다음 범위까지 진행되었다.

- 자율 진화 v1: 8개 페르소나와 100 cycle 완료
- 자율 진화 v2: cycle 101~200 완료
- C1159~C1164: 신격 보구와 무기고 기능, 전투 연동, 비평·로드맵 정리 완료
- C1165: 시공 역설 나선 절차적 엔진과 4종 변칙 생성기 구현
- C1166: 시공 역설 나선 탑 모달과 층계 등반 화면 구현

## 현재 진행 작업

### V4 수익화·재개·결과 화면 안정화

- native purchaseUpdated 이벤트를 검증 후 ad-free entitlement에만 반영한다.
- V4 root 교체·StrictMode·unmount에서 native handle, IAP listener, AdMob banner와
  rewarded ad의 폐기 경계를 유지한다.
- ONE store service 단절 뒤 사용자 구매·복원 액션에서 provider connection을
  재확인하고 listener 등록을 재시도한다.
- 활성 작업 중이거나 최대·비정상 레벨인 시설 강화 버튼을 UI에서 비활성화한다.
- 손상된 오프라인 결과 collection도 빈 안전 상태로 렌더링하고, 재화·장비·작업
  결과를 양수 보상 기준으로 표시한다.
- `output/`, `tmp/` 미추적 사용자 산출물은 작업 범위에서 제외한다.

### 병렬 보호 작업 — C1167

현재 작업 중인 `paradoxSpiral.ts`와 관련 테스트는 이 V4 작업에서 수정하지 않는다.
밸런스·서사·영구 진행 작업은 기존 작업 흐름과 테스트를 보존한 채 별도 진행한다.

### C1167 — 시공 역설 나선 밸런스

- `paradoxSpiral.ts`의 100층 전투 곡선과 방어 계산을 조정한다.
- `paradoxSpiralBalance.test.ts`로 층계별 스탯 증가, 전투 깊이, 경제 보상과 변칙
  효과를 검증한다.
- 변경을 마치면 시스템 테스트, 타입 검사, lint와 전체 회귀 검사를 실행한다.

3. **C1167 밸런스 검증** — 100층 곡선, 변칙 디버프, 보상 경제를 확정한다.
4. **C1168 서사 확장** — 역설 수호자 크로노스와 층계별 마일스톤 전승을 추가한다.
5. **C1169 영구 진행 연동** — 최고 도달층 보너스와 기존 saga 진행을 연결한다.
6. **C1170 종합 비평** — 시스템·밸런스·서사·화면을 함께 검토하고 다음 로드맵을
   갱신한다.
7. **출시 후속** — 원스토어 native wire(Phase 5a-1), Google Play(Phase 5b),
   App Store(Phase 5c)의 순서와 필요성을 검토한다.

## 완료 기준

새 기능은 설계 문서, 구현, 테스트, 검증 결과가 서로 연결되어야 한다. 저장 데이터,
새로 고침, 런 종료, 다음 런 시작과 주요 화면에서 상태가 일관되게 유지되는지
확인한다. 밸런스 변경은 산술 또는 simulation 근거를 남기고, 화면 변경은 모바일
터치 영역과 핵심 E2E 흐름을 함께 확인한다.
